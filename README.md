# Project Progress Tracker — IT 6203 Lab 5 (MongoDB CRUD)

Kennesaw State University · IT 6203 IT Design Studio · Chad Hawkins

An Angular application backed by a Node.js/Express API and a MongoDB database (via Mongoose). Users can **create, read, update and delete** project records. Lab 5 extends the Lab 4 Project Progress Tracker: the predefined in-memory milestones from Lab 4 are replaced with persistent MongoDB documents.

## Architecture

```
Angular App component (localhost:4200)
   │  ProjectService (HttpClient)
   ▼
Express REST API (localhost:8000, backend/server.js)
   │  Mongoose Project model + schema validation
   ▼
MongoDB (local, database: project_progress_tracker)
```

- **Single UI component.** The create/edit form, saved-project list, detail view and delete action all live in the existing standalone `App` component (`src/app/app.ts`, `app.html`, `app.css`). No other UI components were added.
- **HTTP service.** `src/app/services/project.ts` is an injectable service (not a component) that wraps the five API calls.
- **Backend.** `backend/server.js` defines the Mongoose schema and the Express routes. It connects to MongoDB first and only then starts listening.
- **No authentication.** The assignment doesn't require it, and there is no login or user model.

## Data model

| Field | Type / validation |
|---|---|
| `name` | String, required (max 120 characters in the form) |
| `description` | String, required |
| `manager` | String, required |
| `startDate` | Date, required |
| `dueDate` | Date, required; must be on or after `startDate` (checked in Angular and in Mongoose) |
| `status` | `Not Started` · `In Progress` · `Completed` |
| `priority` | `Low` · `Medium` · `High` |
| `completion` | Number, 0–100 |
| `_id`, `createdAt`, `updatedAt` | Generated by MongoDB/Mongoose |

The form has eight user inputs, which exceeds the six-input minimum.

## API endpoints

Base URL: `http://localhost:8000`

| Method | Endpoint | Purpose | Success | Errors |
|---|---|---|---|---|
| POST | `/api/projects` | Create a project | 201 + document | 400 validation error |
| GET | `/api/projects` | List all projects (newest first) | 200 + array | 500 |
| GET | `/api/projects/:id` | Get one project | 200 + document | 400 invalid ID · 404 not found |
| PUT | `/api/projects/:id` | Update a project (runs schema validation via `save()`) | 200 + document | 400 invalid ID/validation · 404 |
| DELETE | `/api/projects/:id` | Delete a project | 200 + `{ message }` | 400 invalid ID · 404 |

Example request body for POST and PUT:

```json
{
  "name": "SIEM Deployment",
  "description": "Roll out centralized log collection",
  "manager": "Jordan Lee",
  "startDate": "2026-11-05",
  "dueDate": "2026-12-15",
  "status": "In Progress",
  "priority": "High",
  "completion": 25
}
```

## Prerequisites

- Node.js and npm (the project uses Angular 22, Express 5 and Mongoose 9)
- MongoDB Community Server running locally on port 27017

## Installation and database setup

1. **Start MongoDB.** Make sure the MongoDB service is running and listening on `127.0.0.1:27017`. On Windows, check with `Get-Service MongoDB`. The `project_progress_tracker` database is created automatically when the first project is saved.

2. **Configure the backend.** Copy the example environment file:

   ```powershell
   cd backend
   Copy-Item .env.example .env
   ```

   `backend/.env` contains `MONGO_URI` and is git-ignored. Don't commit it.

3. **Install dependencies** (the two folders have separate lockfiles):

   ```powershell
   # from the repository root
   npm ci
   cd backend
   npm ci
   ```

## Running the application

Use two terminals.

**Terminal 1: Express API (port 8000)**

```powershell
cd backend
node server.js
# MongoDB connected successfully
# Express server running at http://localhost:8000
```

Run it from inside `backend/` so that `dotenv` finds `backend/.env`.

**Terminal 2: Angular frontend (port 4200)**

```powershell
npm start
```

Then open `http://localhost:4200`.
